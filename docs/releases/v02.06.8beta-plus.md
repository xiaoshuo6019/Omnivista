# v02.06.8beta+ · 生图与算力管理更新

本页 NAS、基础环境与启动器均为测试版本，并非正式版；功能与界面后续仍会调整。

本版包含 NAS 8beta+、Windows 启动器 0.1.9 升级包，以及首次安装使用的 Windows 完整基础环境四个分卷。已有完整环境的用户无需重复下载基础包，也不需要依次安装5、6、7beta补丁。

## 本次更新

### 图片、提示词和界面

- 补齐 v01 的10条默认提示词，支持使用、收藏，保留个人已有收藏。
- 反推能力独立检查模型和运行组件，缺少其他生图工作流时不再影响反推能力识别；缺少模型、组件或可用电脑时显示具体原因。
- 修复图片结果保存后的画廊更新，兼容先上传图片、后完成任务的执行顺序。
- 画廊与“我的文件”统一使用图片下方的操作栏，支持下载、逐图删除和继续编辑。
- 点击图片放大；再次点击大图、背景、右上角 × 或按 Esc 可关闭预览。
- 删除图片时保护未完成任务依赖的输入与结果，远程存储副本删除失败可重试。
- 日志按时间排列并跟随最新内容，调整任务详情按钮、导航宽度、欢迎词和更多功能入口，改善窄屏布局。
- 管理员并入账号卡片列表并排在前面，完善头像、昵称与紧凑编辑。
- 内存管理默认开启并按账号记忆；深色模式同步调整导航、背景和选中项，保留主题色。

### Windows 启动器 0.1.9

- 提供逐项“启动器自检”，检查运行环境与依赖、模型、七份工作流、NAS服务、算力凭据及本机后端。
- 检测结果区分通过、警告与失败，缺少内容时提示对应文件、目录或组件。
- 自检不启动算力、不加载模型、不领取任务、不执行生图。
- 更新反推模型路径识别和能力缺失原因反馈，保留原NAS连接、托盘及按需启动算力的使用方式。
- 可继续配套7beta NAS使用；NAS界面与功能以实际部署的Docker版本为准。

### 首次安装 Windows 本地环境

1. 下载完整基础环境的四个分卷，将 `.001`～`.004` 放在同一目录，保持文件名不变。四卷必须齐全，不能只下载第一卷。
2. 使用7-Zip从 `.001` 开始解压，不要逐卷分别解压。基础运行环境解压后约15.6 GiB，模型另需存储空间。
3. 再下载0.1.9升级包，按下面步骤更新启动器和七个工作流；基础包中的旧启动器不必再运行。
4. 保持程序目录 `Omnivista` 与模型目录 `Omnivista_models` 的既有布局，模型由用户自行准备；首次连接NAS后在Web端确认电脑接入。

**首次安装顺序：完整基础环境四卷 → 解压 → 应用0.1.9累计升级包。** 基础包提供Python、ComfyUI等运行环境；升级包不能单独放进空目录使用，也不包含模型和显卡驱动。

### 已有 Windows 完整环境升级

1. 完全退出旧启动器及托盘，备份旧EXE、配置以及同名工作流。
2. 将升级包中的 `Omnivista Compute Launcher 0.1.9.exe` 放进原 `Omnivista` 程序根目录，将旧EXE移到备份目录，避免误开旧版，并更新快捷方式。
3. 将升级包 `workflows` 内七份工作流复制到原 `workflows` 目录；覆盖前备份同名文件，保留其他自有工作流。
4. 保留 `app`、`runtime`、`private`、模型、日志及缓存，不删除原环境，不复制他人的连接身份。
5. 首次手动打开后连接NAS并保存原配置，核对当前文件名对应的登录自启动；自启动只运行启动器，不自动启动算力。

**已有完整环境只需下载0.1.9累计升级包，无需重下四个基础分卷，也无需按5→6→7→8逐版安装。** 0.1.5和0.1.6的补丁只更新EXE，0.1.7新增的七个工作流已完整包含在0.1.9中。

启动器需要完整环境中的CPython 3.12 x64及对应依赖。各功能按实际模型、工作流和运行组件开放；图片反推仍需对应的Qwen3-VL模型、mmproj和兼容的运行组件。文件自检通过不等于已完成真实GPU生图验证。

同为0.1.9的不同批次EXE内容可能不同，请以本页附件和SHA256校验文件为准。

## NAS 安装与升级

1. 备份原NAS数据卷、图片目录及部署配置。
2. 下载本页Docker TAR及其校验文件，核对SHA256后导入：

```sh
docker load -i omnivista-v02.06.8beta-plus-linux-amd64.tar
```

3. TAR 导入后的本地镜像标签为 `omnivista-native:v02.06.8beta-plus`。参考附件Compose配置原有数据卷、权限与端口，再重新创建容器。也可通过下方 GHCR 固定标签在线拉取，两种方式任选其一。
4. 保留原数据卷，不初始化空数据目录，不删除原账号、图片、任务记录及配置。更新程序不包含个人数据，个人数据依靠原数据卷保留。

### 在线拉取 NAS 镜像

```sh
docker pull ghcr.io/xiaoshuo6019/omnivista:v02.06.8beta-plus
```

已有 Compose 项目仅将 `image` 改为 `ghcr.io/xiaoshuo6019/omnivista:v02.06.8beta-plus`，保留原数据卷、端口和环境变量，再重新创建容器。`compose.image.yaml` 是在线部署参考，`compose.native.yaml` 用于 TAR 导入后的本地镜像部署。

NAS程序为累计更新，不要求逐个导入5、6、7beta镜像。更换Windows启动器也不会自动升级NAS；只换启动器时可以继续使用7beta Docker。
